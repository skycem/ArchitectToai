# 复用判定规则

## 应当复用

- 已有函数/类/服务能覆盖需求，即使名称不完全一致。
- 已有实现需要小改动即可满足，优先扩展而不是新建。
- 场景中已挂载同类脚本/节点，优先复用该场景结构。

## 允许新建

- 搜索后确认没有相近实现。
- 已有实现是测试代码、一次性脚本、与业务无关的示例。
- 需求明确要求新的独立模块/解耦边界，且已有代码无法自然扩展。

## 反例

- 看到 `player_controller.gd` 存在，却新建 `player_movement.gd`。
- 看到 `damage_system.gd` 已有 `apply_damage`，却重新写一个 `deal_damage`。
- 为了“更干净”重写可用的现有模块，而不是在其上迭代。
